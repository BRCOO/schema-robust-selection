# 第二个领域的预注册：Backblaze 硬盘故障预测（2026-11-02 写下）

**写下的时间**：2026-11-02，此时还没有在硬盘数据上运行任何选择方法。只做过四件事：
- 可行性扫描：各厂商上报哪些属性、各有多少故障；
- 在 2024 年第一季度上试跑抽取代码，检查格式和样本量，并据此排除了固态盘；
- 都没有挖掘候选，也没有任何模型或评估的结果。

**目的**：检验方法能不能推广到 ICU 以外的领域。方法完全冻结，规则和 AKI 大池的确认性检验（就绪评估 §5）一样，先写假设，再看结果。

## 1. 数据和任务（`src/icu/v2/extract/backblaze.py`，`scripts/v2/extract_backblaze_cohort.py`）

- **数据**：Backblaze 硬盘数据 2024 年全年（Q1–Q4），公开，不受数据使用协议限制。
- **任务**：硬盘故障预测。
  - **阳性**：某天 T 标记故障的硬盘，窗口是 T 之前 2 天结束的 14 天 [T − 15, T − 2]；每块盘最多一个阳性。
  - **对照**：每个阳性配一块同型号的硬盘（同型号不够时取同厂商），条件是全年不故障、窗口第一天已在数据中、T 之后 30 天仍在（或到数据最后一天）。不放回抽样，种子 20261102。
- **范围**：只用机械硬盘，固态系统盘按型号名排除。
- **特征**：源厂商（希捷）上报的 20 个 SMART 属性。计数和温度用原始值，厂商自定义编码的 1、3、7 号属性用归一化值；没有上报记为缺失，不插补、不缩放。
- **数据库的对应**：
  - 源库：希捷，按硬盘划分 70% / 10% / 20%，种子 20261102；
  - 目标库：HGST、东芝、西数，它们的全部 episode 都作为外部评估；
  - 各厂商的 schema：在 ≥ 95% 的 episode 窗口里至少出现一次的属性。
- **不设模拟的缺失目标**，目标平均只算三个真实厂商。

## 2. 方法和对照（完全按 ICU 上的设置，不做任何调整）

- **生成器**：PrefixSpan、ERMiner、matrix profile、shapelet，参数和 ICU 相同（minsup 0.2，候选池上限 200，长度 3–5，每个特征取前 3 个，4 个分位数档）。FMG 不用。
- **选择**：
  - 用 `run_union_selection.py` 跑，已知目标为 HGST、东芝、西数；
  - 再用 `run_union_extra.py` 加跑「不给目标 schema 的 SRS-C-V」、JMI、CMIM、L1 + schema 丢弃训练，以及压力曲线。
- **SRS-C-V**：丢弃率 q 在验证集上从 {0, 0.25} 中选；快速版短名单 10；每个程序最多 5 个代理；探针 C 在验证集上选。
- **硬盘属性的粗分组**（`types.DRIVE_GROUP_BY_FEATURE`）供 schema 丢弃使用，看结果前已固定。
- **预算**：K = 10 是主设定，K = 5 和 20 是次要设定。

## 3. 预先写下的假设（K = 10）

1. **H1**：SRS-C-V 对 mRMR，内部 AUPRC 和目标平均 AUPRC（都加代理部署）都显著更好。
2. **H2**：SRS-C-V 对 MMRFS 和 L1，两个指标都显著更好。
3. **H3**（只用源数据的设定）：不给目标 schema 的 SRS-C-V 对 mRMR，目标平均 AUPRC 显著更好。

显著以病人聚类配对 bootstrap 的 95% CI 为准；这里的病人对应硬盘。

### 6.4 解读（事后分析，不改变判定）

- **内部 AUPRC 有天花板**：几种好的方法内部都在 0.86–0.92 之间。它们都抓到了同一个主导信号 187（报告的不可纠正错误），选择方式影响不大，和 ICU 单一生成器池上各方法趋同是同一个现象。
- **迁移到其他厂商时的优势基本复现**：在 3 个预算 × 全部对照上，目标平均只有 1 格更差，即 K = 10 对 L1 + schema 丢弃训练。
  - 那一格的原因：L1 + 丢弃训练选了更多 5、197、198 这类介质错误程序，这些属性各厂商都有、含义也一致；
  - SRS-C-V 仍主要依赖 187，在目标库上只能靠代理接替。
- **把代理放进选择目标在这里很关键**：选择时不考虑代理的 SRS（`srs_known`），K = 10 时目标平均只有 0.661，SRS-C 是 0.752。
- **新的局限，ICU 里不明显**：有些属性各厂商都上报，但含义或刻度不同。例如 1 号读错误率的归一化值、193 号加载循环计数，各厂商取值范围不同。所以程序能执行不等于迁移后还准，而 SRS 的目标只建模了能否执行。
- **不给目标 schema 的版本**：K = 5 时验证集选了 q = 0，于是退化成不看 schema 的选择，目标平均比 mRMR 低 0.124。所以在这个领域，已知目标 schema 帮助很大。
